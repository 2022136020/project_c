## AI 사용법

**1. 선택지 먼저 물어보기**
"만들어줘"보다 "어떤 선택지가 있냐"고 먼저 물어보는 게 더 좋은 결과가 나온다. 직접 구현을 지시하면 AI가 가장 흔한 방법을 바로 써버리지만, 선택지를 물으면 트레이드오프를 보고 내가 고를 수 있다.

**2. 지시를 좁혀야 원하는 결과가 나옴**
모호한 지시를 줄수록 AI가 원하지 않는 방향으로 구현한다. 조건과 범위를 먼저 좁혀서 지시해야 한다.

**3. AI가 만든 코드도 직접 검토해야 함**
실행 결과만 보면 버그를 놓친다. 코드를 읽고 내가 이해한 뒤 넘어가야 나중에 수정할 수 있다. 이번 프로젝트에서 `deleteAccount` cascade 미처리 등을 코드 리뷰로 발견했다.

**4. 단계 나눠서 요청하기**
한 번에 너무 많은 걸 요청하면 중간 결과가 흐릿해진다. 하나씩 끊어서 요청하고 확인한 뒤 다음 단계로 넘어가는 게 효율적이다.

## 개발 과정

**5. 기술 선택 이유를 문서로 남겨야 함**
나중에 본인도 왜 그렇게 결정했는지 기억 못한다. ADR(Architecture Decision Records)로 선택지와 이유를 기록해두면 발표 Q&A에서도 바로 답할 수 있다.

**6. 화면·로직·저장을 분리하면 유지보수가 쉬워짐**
한 곳만 고쳐도 나머지가 안 깨진다. screens / services / models 역할을 나눠두니 Firebase를 수정해도 화면 코드는 건드릴 필요가 없었다.

## Flutter 실행 환경

**7. Windows에서 `flutter run -d windows` 실패 가능**
심링크 권한 때문에 Windows Developer Mode가 비활성화되어 있으면 실행이 안 된다. 이 경우 `flutter run -d chrome`으로 웹 버전으로 대체할 수 있다.

**8. Flutter 모바일 앱도 Chrome으로 실행 가능**
`flutter run -d chrome` 명령어로 웹 빌드를 띄울 수 있다. 모바일과 동일한 UI를 브라우저에서 빠르게 확인할 때 유용하다.

## Claude Code 도구

**9. 커스텀 에이전트 호출은 CLI에서 `@에이전트명`**
`.claude/agents/`에 만든 에이전트를 Agent tool의 `subagent_type`에 넣으면 작동하지 않는다. Claude Code CLI에서 직접 `@feature-debugger` 형태로 호출해야 한다.

## python-pptx

**10. 좌표 단위가 EMU라 Inches() 변환 필수**
`Inches()`, `Pt()` 변환 함수 없이 숫자를 그대로 쓰면 위치가 완전히 틀어진다. 처음에 단위를 모르고 쓰다가 텍스트가 슬라이드 밖으로 나갔다.

## 아키텍처 의사결정

**11. ADR은 "왜"를 기록하는 문서**
Context(왜 결정이 필요했나) / Decision(무엇을 골랐나) / Consequences(결과와 트레이드오프) 세 섹션으로 구성된다. 번호 순서가 결정 순서이고, 나중에 번복해도 기록이 남는다.
