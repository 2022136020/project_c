========================================
WBS란?
========================================

WBS = Work Breakdown Structure (작업 분해 구조)

프로젝트 전체 작업을 기능 단위로 쪼개서 계층적으로 정리한 계획 도구입니다.
큰 목표 → 중간 기능 → 세부 태스크 순서로 내려가며, 각 항목에 담당자·기간·진행률을 붙입니다.
이번 프로젝트에서는 1.인증 / 2.계좌관리 / 3.포지션관리 / 4.시각화 / 5.대시보드 / 6.문서배포
6개 카테고리로 나누고, 간트 차트 형태로 주차별 일정을 표시했습니다.

발표 중 WBS가 나오면 한 문장으로:
"전체 기능을 6개 영역으로 나누고 주차별 일정을 간트 차트로 관리했습니다."

========================================
예상 Q&A
========================================

Q. WBS가 뭔가요?
A. Work Breakdown Structure, 작업 분해 구조입니다.
   프로젝트 전체 기능을 쪼개서 계층적으로 정리하고 주차별 일정을 붙인 계획 도구입니다.
   이번 프로젝트는 인증·계좌·포지션·시각화·대시보드·문서 6개 영역으로 나눴습니다.

Q. pre-presentation-checker가 실제로 얼마나 유용했나요?
A. 발표 전 점검할 때 제출 서류 목록을 하나씩 뒤지는 시간을 절약했습니다.
   /pc 하나로 미완료 항목이 리스트업되니 어디부터 준비해야 할지 바로 파악됩니다.

Q. 단계별 보고 방식이 일반 개발과 어떻게 다른가요?
A. 일반적으로는 AI가 코드를 만들면 실행만 해보고 넘어가지만,
   이 방식은 AI에게 설명을 요청해서 내가 이해했는지 확인한 뒤 넘어갑니다.
   AI가 만든 코드도 내 코드처럼 설명할 수 있어야 한다는 원칙입니다.

Q. AUTHORING.md를 왜 단일 파일로 만들었나요?
A. 에이전트 설정, 커스텀 명령어, 행동 규칙을 파일마다 따로 관리하면
   새 프로젝트를 시작할 때마다 다 다시 세팅해야 합니다.
   하나로 묶으면 파일 하나만 주면 됩니다.
