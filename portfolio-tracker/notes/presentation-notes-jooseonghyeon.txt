주성현 발표 대사 (4분)


[ 슬라이드 1 — 표지 ] (20초)
안녕하세요. Portfolio Tracker를 발표할 주성현입니다.
"되돌아보는 투자자가 앞으로 나아간다" — 이 한 문장이
이 앱을 만든 이유입니다.


[ 슬라이드 2 — 문제 정의 ] (40초)
개인 투자자가 겪는 문제는 세 가지입니다.
첫째, 투자 데이터가 여러 계좌에 흩어져 전체 현황을 한눈에 볼 수 없습니다.
둘째, 체계적인 기록 수단이 없어 복기가 불가능합니다.
셋째, 복기 없이는 같은 실수가 반복됩니다.
저도 직접 투자하면서 이 고통을 겪었고, 이것을 해결하는 앱을 만들었습니다.


[ 슬라이드 3 — 활용 방안 ] (30초)
이 앱으로 세 가지를 할 수 있습니다.
주식·코인 계좌를 한 곳에서 관리하고,
매수 근거와 실제 손익을 나란히 놓아 복기하며,
차트와 대시보드로 성과를 지속적으로 추적합니다.


[ 슬라이드 4 — WBS ] (25초)
WBS는 Work Breakdown Structure, 작업 분해 구조입니다.
전체 기능을 인증·계좌·포지션·시각화·대시보드·문서 6개 영역으로 나누고
주차별 일정을 간트 차트로 관리했습니다.
보시다시피 모든 항목이 100% 완료되었습니다.


[ 슬라이드 5 — 사용자 시나리오 ] (25초)
핵심 사용 흐름은 이렇습니다.
로그인 → 계좌 등록 → 포지션 진입 기록 → 포지션 정리 → 복기 메모.
예를 들어 삼성전자를 68,000원에 매수하고
72,000원에 매도하면 수익률과 손익이 자동 계산됩니다.


[ 슬라이드 6 — 기술 스택 ] (25초)
기술 선택은 세 가지 ADR로 결정했습니다.
모바일 프레임워크는 Flutter,
백엔드는 Firebase Auth와 Firestore,
아키텍처는 4레이어 구조입니다.
각 선택의 이유는 발표 뒷부분 ADR 슬라이드에 정리했습니다.


[ 슬라이드 7 — 아키텍처 ] (25초)
4레이어 구조는 화면·흐름·규칙·저장으로 역할을 분리합니다.
Firebase를 수정해도 화면 코드를 건드릴 필요가 없고,
계산 로직이 바뀌어도 저장 코드는 그대로입니다.
이 구조 덕분에 유지보수가 쉬웠습니다.


[ 슬라이드 8 — 데모 ] (20초)
지금 바로 시연해 보겠습니다.
계좌 등록부터 포지션 기록, 차트 확인까지
실제 앱에서 보여드리겠습니다.

--- (시연) ---


[ 슬라이드 9 — 차트 ] (15초)
이 화면이 포트폴리오 분석 화면입니다.
종목별 수익률 막대 차트와 누적 손익 라인 차트를
기간 필터로 구분해서 볼 수 있습니다.


[ 슬라이드 10 — 개발환경·빌드·배포 ] (20초)
개발 환경은 Flutter SDK, VS Code, Firebase CLI입니다.
빌드는 flutter build apk로 APK를 생성하고,
Firebase Hosting으로 웹 배포도 가능합니다.
자세한 내용은 GitHub README와 docs 폴더에 정리했습니다.


[ 슬라이드 11 — 코드 품질·테스트 ] (20초)
코드 품질은 flutter_lints로 린트 경고 0건을 유지했고,
StreamBuilder로 불필요한 폴링을 제거해 성능을 최적화했습니다.
테스트는 인증·계좌·포지션·차트·대시보드 5개 영역을
직접 시나리오로 수행했습니다.


[ 슬라이드 12 — 어려운 점 ] (20초)
개발하면서 세 가지 어려움이 있었습니다.
iOS 빌드는 Mac 환경이 없어 Android APK만 제출합니다.
Firebase 보안 규칙 검증과 APK 배포 절차는 처음 경험해서
도움이 필요한 부분입니다.


[ 슬라이드 13 — 향후 계획 ] (25초)
앞으로 실시간 주가 자동 조회 기능을 추가할 계획입니다.
현재는 진입가와 수량을 직접 입력해야 하는데,
Yahoo Finance API를 연동해 포지션 등록 시 현재가를 자동으로 불러올 예정입니다.
REST API 연동과 API 키 보안 관리를 새로 학습해 적용할 것입니다.


[ 슬라이드 14·15 — AI 워크플로우 ] (30초)
개발 방식에서 세 가지 기법을 사용했습니다.
첫째, feature-debugger 에이전트를 직접 제작해 6개 기능 영역을 반복 점검했습니다.
둘째, AUTHORING 파일 하나에 Rules·Skills·Commands를 통합해
새 프로젝트에서도 AI 운영 체계를 즉시 세팅할 수 있게 했습니다.
셋째, 단계별로 개발하고 직접 이해한 뒤 다음 단계로 넘어가는 워크플로우를 유지했습니다.

이상입니다. 감사합니다.
